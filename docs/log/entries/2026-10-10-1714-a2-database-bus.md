# A2: database bus mapped from the migrations at 02ab37e

## What was done
- Read-only subagent mapped all 41 SQL migrations in `PROVES_LIBRARY/supabase/migrations/`
  to their final state: tables, views, functions, triggers, RLS, grouped into nine areas.
- Re-checked the most serious claims by hand (grep/sed on the migration files).
- Recorded the result in `docs/decomposition/proves/database-bus.md`.

## What was found / decided
- The migrations are not a faithful record of the live DB (it came from a Neon dump):
  035 missing, 036 duplicated, objects referenced but never created (`kg_*`,
  `core_equivalences`, ~20 tables in 032's RLS).
- Verified defects: `promote_to_verified_knowledge` (009) inserts columns that `011:92-93`
  drops and is never redefined; `record_review_decision` writes values the `005b:13` CHECK
  rejects (`019:290`); the org trigger reads `NEW.source_id` that no migration adds
  (`023:454`); anon can execute the review-writing RPCs (`033:26-27`).
- No RLS policy isolates staging, decisions or the library by organization.
- Many duplicate models (relationships ×4, aliases ×3, review state ×4, tenancy ×2).
- Decided (working): the neutral standard must be derived from what the modules actually
  use, not by replaying PROVES migrations. Spine areas A (staging) → B (decisions) →
  C (library) + D (lineage) match the draft `spine.sql` shape; E–I are module-owned.

## Lessons
A schema folder in a prototype can diverge from the running database; check it against
what the code actually calls (A1) before treating it as the standard.

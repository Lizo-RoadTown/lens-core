# Log index: one index of every Lens module's log, with consistency and audit

## What was done
Built roadmap item `log-index-action` to lens-log DESIGN.md section 3.5:
- `scripts/log_index.py` (standard library plus git) writes `docs/log/INDEX.md`:
  - **Built from:** the commit each repo was read at.
  - **Consistency:** each piece must have `role: piece`, its own module name, and only
    sources the whole declares.
  - **Audit:** commits that changed a declared surface without adding a log entry, counted
    from the repo's first log entry so earlier history is not flagged. This is the backstop
    for shell edits the hooks cannot see.
  - **Misses:** every `docs/log/missed/` marker.
  - **Entries:** a table with links.
  - Exits 1 on consistency problems.
- `tests/test_log_index.py`: 8 tests on throwaway git repos; the suite has 25 passing.
- `.github/workflows/log-index.yml`:
  - runs daily, on demand, and on push to main;
  - checks out the four siblings and commits INDEX.md when it changes;
  - fails on consistency problems.
- Local run: 35 entries, all four pieces consistent, no misses, one audit row
  (lens-core 7412b60 edited `docs/BUILD.md` without an entry in that commit).

## What was found / decided
The audit is informational, not failing: an entry committed separately from its change shows up
too, so each row needs a human look. Consistency problems fail the job because they mean a
repo's declaration has drifted from the whole. The item stays in progress until the workflow
has run green on GitHub.

## Lessons
On Windows, git object files are read-only, so tests should move a repo away rather than delete
it.
